# TurboMPC 原生移植审查

审查对象：冻结提交 `a771284` 相对共同基线 `3e1b459` 的 M0–M4 改动。
两个独立审查轴分别检查工作区规则/代码风险和用户阶段/验收要求。
原工作树中其他进程的 M5 草稿不属于此次审查范围；未改动的 MIT 上游 CUDA 内核只检查出处和显式差异。

## Standards

### P2：实验记录可能被同名输出覆盖

`benchmark_turbompc.py` 原先直接写 JSON/NPZ；paired 脚本只预查 JSON，且带点号的输出名称可能使两个 NPZ 路径合并。
这违反工作区要求保留历史实验和失败记录的规则。

已修复：在运行前检查全部输出路径，保存时使用独占创建模式 `x`/`xb`。
含点号名称保留完整 stem，单端 JSON/NPZ 路径重合直接拒绝。
13 项 CPU 临时目录检查通过，包括检查后文件才出现的竞争情况；既有内容未被修改。

### P3：高层直接包装底层私有方法

`TorchMPC` 为编译优化替换 `NativeADMM._schur`。可以将编译选项归入 `NativeADMM` 自身以减少层间依赖。
这是维护性建议，没有发现对应运行错误。本轮保留已冻结并实测的求解路径，不进行无必要重构。

### 生命周期与来源

Python 缓存和 C++ workspace 都使用明确的 solve/close 互斥。
C++ 先释放 GIL，再取得 workspace mutex；释放 mutex 后才重新取得 GIL，关闭使用相同锁。
按 Stream 隔离的 ADMM 工作区、外部 Stream 寿命要求、MIT 出处和 KKT IR2 差异均有文档。
两套 CUDA 上的并发关闭及 Stream 回归通过，审查没有发现新的生命周期缺陷。

## Spec

### P2：历史自定义 backend 诊断被永久纳入正式门槛

冻结版 `check_acceptance.py` 让旧 custom-backend 文件的缺失或失败永久否决 M4，未读取新执行的完整官方接口复测。
历史证据应该保留，但需要用同一固定输入、同一原版库的官方复测判定已知问题是否仍存在。
这一门槛逻辑问题不影响本轮失败结论：四状态正式测试和九状态完整官方测试各自已有独立梯度失败。

已修复：通过 `--official-regression-report` 检查官方身份、同一 A 库/源码、固定输入和求解参数，并从 NPZ 重新计算梯度及物理约束门槛。
缺失、失败、不同输入/库和 IR2 候选报告均不能被原版 gate 接受。16 项 CPU 单元测试通过；合规合成通过样本不会再被历史失败永久挡住。
正式数值与计时运行函数保持逐字不变。独立 CPU 重评报告保留原测量的提交和哈希，M4 仍为 false，没有改写原始 GPU 记录。

### 验证覆盖边界

原有测试覆盖解析 QP、最终轨迹、有限差分、Stream 和失败批次，但没有单独展示每次 SQP 的 QP 组装及 A/B 原始状态一致性。
因此进度文档已将 M1/M2 的表述限定为“已实现，目标回归通过”，不声称完整上游 API 等价。
逐次 QP 审计作为独立报告补充，不用最终轨迹一致性代替内部数据比较。

已补充的 B1/N15 官方线性审计全部通过：两端逐次 ADMM 均 `[50,25]`，QP 数据最大差异 `1.39e-17`；相同可行 QP 与初态等式/盒上界矛盾的不可行 QP，其状态分别一致为 SOLVED 和 PRIMAL_INFEASIBLE。
这补齐固定用例的直接证据；不扩展成所有动力学、约束模式或失败路径的穷尽证明。

### 阶段与基线

共享 GPU 计时符合用户最新要求。正式 A 保留未修改的 `7050a4f` 官方 `MPCBackend` 和 PyTorch 桥接。
原生梯度的有限差分通过不能代替 A/B 梯度门槛；独立 IR2 候选也不能冒充未修改的原版 A。
冻结审查时，未修改原版 A0 的 M4 失败，因此当时未进入 M5，没有将只读接口核对记为 M5 完成。

独立 IR2 候选的四个 Batch、400 对计时与全部数值/有限差分检查随后均通过，且原版安装库未变。
候选原始报告仍固定 `m4_gate_passed=false`。用户再次要求继续后，本轮明确采用两端共同 IR2 的配置；
独立汇总验证通过并保存 `baseline_role=upstream_7050a4f_plus_ir2`，原版 A0 失败独立保留，然后开始 SFC 接入。
门槛修复、逐次 QP 审计及候选完整实验的结果在进度文档与对应原始报告中记录。
