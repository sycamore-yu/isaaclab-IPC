# AC-MPC 路径进度实施计划

> 沿用用户已确认的 P1–P3：实现、必要检查、训练与真实闭环对照。

**目标：** MINCO 提供空间曲线，AC-MPC 联合选择 CTBR 与路径进度，比较实际到达效率。

**架构：** 保留 10D 物理模型，增加弧长状态 s 和虚拟进度速度 nu。用原 SFC 限制位置，用走廊弧长区间限制 s。每次规划固定几何线性化与走廊分配；同一观测的 PPO 重放不调用前端。

**技术栈：** 当前 Torch、TurboMPC CUDA/cuDSS、PathCover、Newton、MARSIM/Flightmare；不增加控制器或求解器。

## 实施任务

- [x] `ctbr_progress.py`：从 MINCO 构建弧长参考，按实际运动的进度初值选择有序 SFC。测试时间重参数化不改变几何与走廊映射。
- [x] `turbompc/progress.py`：11D 状态、5D 优化输入；物理执行仍为 4D。保留 140D CTBR 成本头，在局部切线模型上增加滞后误差、速度一致性及固定进度奖励。测试新增进度导数、PSD 成本和一次 KKT 反向。

- [x] 固定成本 Newton、Actor 训练、固定与学习成本的 5 种子 Newton 配对和 Dense / High-speed 4 场完整 MARSIM 闭环均完成。Rerun 已保存。
- [x] 实测记录、失败样本和完整配对结果见 `docs/acmpc-progress.md` 与 `results/acmpc-progress-20261115-v2/paired-v5-summary.json`；源码和必要测试单独提交，不包含用户原有未提交修改。

## 数值决策

首版使用每次规划固定的局部切线近似 r(s)=r(s_bar)+t(s_bar)(s-s_bar)。这是实际被优化的局部 MPCC 问题，其成本对位置与进度的交叉项进入同一个 KKT 系统。无需改写 CUDA QP 或重验证已有 CTBR 导数。

实际状态在每次局部重规划的曲线起点，因此局部 s0=0；不累加旧曲线的虚拟进度。每个节点的原 SFC 与弧长区间作为一个快照保存。使用物理到达时间评价收益。

## 验证范围

只测试新增动力学/成本耦合、走廊交界和一次成本梯度。沿用现有残差与碰撞指标。完成固定成本闭环后再训练，不预设必须提升的百分比。
