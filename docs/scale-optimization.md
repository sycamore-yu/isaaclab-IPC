# AME-2 式共享显存与 IPC 并行优化

当前默认使用共享森林 BVH、索引式 Mid-360 射线和无损 SFC 快照。
主程序仍由 Isaac Lab 管理场景、传感器更新、环境隔离和重置。
没有合并各环境的物理状态，也没有向规划器提供全图真值。

## 实现

`compact_sensor.py:SharedMid360RayCaster` 继承 Newton 的 `LegacyMultiMeshRayCaster`。
官方实现继续发现查询目标、建立每环境网格表、跟踪位姿与移动障碍。
对明确声明 `is_shared=True` 的相同局部几何，只创建一个 Warp Mesh/BVH。
不同缩放分别缓存；未声明共享的目标继续独立加载。

射线只保存一份 `800000×3` float32 方向表、每环境窗口索引和命中点。
融合 Warp 内核按需计算射线起点、方向及网格局部坐标，不保存四组 `E×R×3` 中间缓冲。
逐射线选取最近目标，也不需要逐射线距离工作区。
查询仍使用 Warp `mesh_query_ray`；没有修改安装包。

保持 20,000 rays、10 Hz、40 m、随机连续窗口、机体原点及轴对齐安装。
保留 300 Hz Newton、100 Hz 控制、完整 PCD 与 0.25 m 碰撞半径。
同批更新共享扫描窗口，局部 reset 只影响指定环境。

`frontend.py` 将点云过滤后的传输合并为每批一次。
独立 Planner 可通过有界线程池调度，结果按环境顺序返回。
默认仍用 1 个工作线程：4 线程降低了更新地图时的尾延迟，但缓存命中时调度开销更大。

`Planner` 缓存同一地图、种子和安全半径下的 RISP 多面体。
当前原生接口的终点只用于检查包含关系，不参与多面体生成。
因此长走廊的多个候选终点复用同一结果，再分别检查原有 `1e-8` 包含容差。
每次点云更新清空缓存，最多保留 32 个种子；无效种子也按相同条件缓存。

`corridor_storage.py` 保存两组非空走廊及 15 个预测步的索引。
平面保持 float64、原始行序和独立快照；空走廊索引为 -1。
MPC 与 Rerun 读取时还原完整约束。旧的展开观测仍可读取。
超过平面容量或两组走廊时直接报错，不截断约束。
QP 的 CUDA Graph 工作区采用最多 4 种形状的 LRU 缓存，避免有效环境数变化时无限增长。

## 验证环境

本机 RTX 4090，其他训练持续占用 GPU。所有耗时均来自共享设备，不作为独占吞吐保证。
Isaac Lab 3.0.0、Newton 1.6.1、Warp 1.17.0、Torch 2.11.0+cu130、RSL-RL 5.5.1。
现有功能基线单独保存在提交 `7234a77`，此前主分支为 `7e0dba1`。
证据目录为 `results/ame2-scale-20261103T000820/`。

## 显存与射线

| 测试 | 官方基线 | 优化版 |
| --- | ---: | ---: |
| 双环境森林 Mesh ID 数 | 2 | 1 |
| 双环境进程显存采样，初始化后 / 步进后 | 1,552 / 1,616 MiB | 1,102 / 1,168 MiB |
| 8 环境森林 Mesh ID 数 | 8 | 1 |
| 8 环境进程显存采样，初始化后 / 步进后 | 4,418 / 4,482 MiB | 1,122 / 1,186 MiB |
| 64 环境进程显存采样，初始化后 / 步进后 | 未运行 | 1,202 / 1,286 MiB |
| 256 环境森林 Mesh ID 数 | 未运行，避免大量重复几何分配 | 1 |
| 256 环境进程显存采样，初始化后 / 步进后 | 未运行 | 1,394 / 1,618 MiB |
| 256 环境主要射线缓冲 | 312.50 MiB，按原缓冲形状计算 | 58.59 MiB，实际分配大小 |

主要射线缓冲减少 81.25%，不包含两版都有的共享方向表和 BVH。
8 环境步进后进程显存采样下降约 73.5%；初始化耗时在本次配对中为 60.34 → 10.56 s。
`nvidia-smi` 数值为本次进程的显存采样，包含 Warp/Newton，不是全过程峰值。
256 环境验证覆盖传感器、物理、窗口更新和局部重置，不代表 256 环境完整 PPO 训练通过。

双环境保存的初始与步进后点云，与官方基线的命中掩码、坐标及体素归属完全一致。
早期内核用世界系重建命中点，产生微米误差却改变了部分体素归属。
最终实现改为与官方相同的局部坐标重建顺序，相关对照误差为 0。

实际射线查询必须使用全有效环境掩码。仅调用 `update(0, force_recompute=True)`
不会将已更新环境标记为过期，会测到空查询。旧的非 `*-active` 计时不用于性能结论。
最终双环境查询中位数为官方 0.775 ms、优化版 1.193 ms，未显示小批量查询加速。
8 环境查询中位数为 0.981 → 0.861 ms，但优化版 P95 更高；共享 GPU 下不主张稳定查询加速。
优化版 64 环境全射线查询中位数为 6.37 ms。
256 环境全射线查询中位数为 28.64 ms，P95 为 37.36 ms。
这些是传感器查询时间，不包含 A*、SFC、QP 或 PPO。

## 规划与训练存储

同一已观测点云、8 环境、20 次规划回放：

| 执行方式 | 总耗时 | 原生走廊生成次数 | 输出 |
| --- | ---: | ---: | --- |
| 原逻辑，单线程 | 2,338.27 ms | 1,472 | 基线 |
| 精确缓存，单线程 | 623.32 ms | 64 | SHA-256 与基线一致 |
| 精确缓存，4 线程 | 568.12 ms | 64 | SHA-256 与基线一致 |

单线程缓存加速约 3.75 倍；4 线程组合约 4.12 倍。
这是 CPU 规划回放，不是整轮 PPO 训练加速。
4 线程的中位延迟高于缓存单线程，故未设为默认。

256 环境、64 步 rollout 的 SFC 平面数组由 240 MiB 降为 32 MiB。
计入有效掩码和 int64 时序索引后，相关上下文为 34.875 MiB，原展开形式为 247.5 MiB。
这是存储形状的字节计算，不是整个训练进程显存。
原始与压缩快照生成的 QP 数组、动作和打乱后的样本对应关系已验证。

## 使用

优化是默认入口，无须改原训练命令。
经典评测可显式增加 `--planner-workers 4`；AC-MPC 使用 `env.planner_workers=4`。

```bash
env -u PYTHONPATH OMP_NUM_THREADS=1 uv run python scripts/benchmark_scale.py \
  --sensor compact --num-envs 256 --output results/my-scale-256
env -u PYTHONPATH OMP_NUM_THREADS=1 uv run python scripts/benchmark_scale.py \
  --sensor official --num-envs 2 --save-hits --output results/my-reference
env -u PYTHONPATH OMP_NUM_THREADS=1 uv run python scripts/benchmark_scale.py \
  --sensor compact --num-envs 2 --save-hits --output results/my-compact
uv run python scripts/compare_sensor_runs.py results/my-reference results/my-compact \
  --output results/my-sensor-parity.json
```

CPU 前端回放使用 `benchmark_frontend.py --cloud observed-cloud.npy`。
输入应为实际传感器观测，不以完整 PCD 替代。

## 保留的边界

本轮没有将 GPU 体素聚合、体素表面共面合并或共享全图规划设为默认。
已经发现微小射线舍入差异会改变体素归属；这些候选需要独立证明地图与轨迹等价。
当前 CPU 点云历史与 A* 网格仍按环境保存，可能限制更大的完整训练规模。
没有运行中高速、长森林、多种子或长期 PPO 收敛评测。
不从本轮内存优化推断中速失败已修复。
